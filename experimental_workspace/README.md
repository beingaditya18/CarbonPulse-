# CarbonPulse AI+ — Experimental Workspace Architecture

This directory serves as the isolated, reproducible staging ground for the eight peer-review scientific experiments expanding upon the original CarbonPulse baseline.

---

## 1. Directory Structure & Functional Purpose

```
experimental_workspace/
├── configs/                  # Centralized, immutable YAML configurations
│   ├── global.yaml           # Global environment, hardware, random seeds, and directories
│   ├── data.yaml             # Dataset schemas, file references, leakage rules, and column mappings
│   ├── models.yaml           # Model architectures, hyperparameters, and execution flags
│   └── experiments.yaml      # Specific configurations for all 8 experimental modules
├── data/                     # Data artifacts specific to experimental expansions
│   ├── manifests/            # Cryptographic manifests and data dictionaries
│   ├── external/             # Registry schemas and metadata for external jurisdictions (NYC, Boston)
│   ├── validation/           # Data validation logs, schema audit outputs, and discrepancy reports
│   └── splits/               # Isolated building-level split indices (train, calib, test)
├── src/                      # Source code for experiment execution and utilities
│   ├── data/                 # Reusable data validation and schema checking logic
│   ├── splits/               # Leakage-free building-level split manager
│   ├── utils/                # Experiment registry, logging, and metrics computation
│   └── experiments/          # Dedicated submodules for each scientific investigation
│       ├── risk_control/     # Exp 1: Formal conformal risk-control & error rate bounding
│       ├── tabnet/           # Exp 2: TabNet deep tabular baseline with sparse attention
│       ├── perturbation/     # Exp 3: Full 757-building physical GFA perturbation diagnostic
│       ├── weighted_conformal/# Exp 4: Locally weighted & conditional conformal evaluation
│       ├── paired_audit/     # Exp 5: Paired audit-budget statistical significance testing
│       ├── shap_subgroups/   # Exp 6: Size-class and typology SHAP attribution stability
│       ├── mahalanobis/      # Exp 7: Regularized Mahalanobis distance & applicability domain
│       └── external_validation/# Exp 8: Cross-municipal schema harmonization interface
├── tests/                    # Unit and integration tests for setup, splits, and data loading
├── logs/                     # Structured execution and audit logs
├── results/                  # Structured CSV/JSON experimental outputs (no manual values)
├── figures/                  # Vector/raster visualizations generated by experiments
└── reports/                  # Detailed markdown audit and evaluation reports
```

---

## 2. Scientific Separation Principles

1. **Read-Only Baseline:** The original baseline dataset (`data/raw/` and `data/processed/`) and models (`models/`) remain strictly immutable.
2. **Facility-Clustered Independence:** All data splitting is conducted at the unique facility identifier level (`OSEBuildingID`). No individual facility may exist across multiple partitions (e.g. training and test).
3. **Reproducibility Guarantee:** Random seeds, package versions, hardware specs, and configuration hashes are recorded in the central registry for every experiment run.
4. **No Premature Execution:** In this setup-only phase, all experiment modules are scaffolded with strict input interfaces, test coverage, and documentation. No scientific results are generated without explicit authorization.
